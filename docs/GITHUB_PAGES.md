# Запуск через GitHub Pages и Actions

Короткий ответ на вопрос из issue #1: **частично да**.

Проект состоит из двух независимых частей:

| Часть | Что это | Можно ли на GitHub Pages |
|-------|---------|--------------------------|
| `evolute_client.html` | статический веб-клиент (HTML + JS, работает в браузере) | ✅ **да**, публикуется одной кнопкой |
| `evolute_api.py` | Flask-прокси: постоянно живущий процесс, фоновые таймеры обновления токенов, запись файлов `dump.json` / `status.json` / токенов, секреты `API_KEY`, `CAR_ID` | ❌ **нет** |

## Почему прокси нельзя на Pages/Actions

GitHub Pages — это **только раздача статических файлов**: там нет Python,
нет открытых портов, нельзя выполнить серверный код. `evolute_api.py`
поднимает `app.run(host=LISTEN, port=PORT)` и держит два `threading.Timer`
(`periodic_refresh`, `periodic_fetch`) — для этого нужен постоянно
работающий сервер.

GitHub Actions тоже не подходит как хостинг: раннер — временная машина,
job принудительно убивается (лимит 6 часов), у него нет постоянного
публичного адреса, а токены Evolute (`evy-platform-access` /
`evy-platform-refresh`) нужно хранить и переписывать между запусками.

Итог: **клиент — на Pages, прокси — на своём хосте** (VPS, домашний
сервер, Raspberry Pi, любой PaaS с постоянным процессом). Ровно так это
и задумано: клиент из браузера ходит на ваш `Base URL`.

---

## Шаг 1. Включить Pages

1. Settings → Pages.
2. **Source: GitHub Actions** (не «Deploy from a branch»).
3. Всё. Workflow `.github/workflows/pages.yml` уже лежит в репозитории.

## Шаг 2. Задеплоить

Деплой запускается автоматически при push в `main`, если менялся
`evolute_client.html` или сам workflow. Запустить руками:
Actions → **Deploy web client to GitHub Pages** → *Run workflow*.

Workflow копирует `evolute_client.html` в `_site/index.html`
(плюс оставляет копию под исходным именем) и публикует артефакт.

После успешного прогона клиент доступен по адресу:

```
https://<ваш-логин>.github.io/<имя-репозитория>/
```

## Шаг 3. Поднять прокси там, где он может жить

На своём сервере (см. основной README):

```bash
git clone <этот-репозиторий>
cd evolute_proxy_webclient
nano docker-compose.yml     # CAR_ID, API_KEY, API_KEY_RW
docker-compose up --build -d
```

Прокси должен быть доступен браузеру, который открывает страницу Pages.

> ⚠️ Страница на Pages отдаётся по **https**. Браузер запрещает
> запросы с https-страницы на **http**-адрес (mixed content).
> Поэтому у прокси должен быть **https** (например, nginx/Caddy с
> Let's Encrypt перед ним) — либо открывайте клиент локально,
> просто дважды кликнув по `evolute_client.html`.

## Шаг 4. CORS

Клиент на `*.github.io` и прокси на вашем домене — это разные origin,
поэтому прокси обязан отдавать CORS-заголовки. В `evolute_api.py` это
уже сделано (`add_cors_headers`), origin настраивается переменной:

```yaml
environment:
  ALLOWED_ORIGIN: "https://<ваш-логин>.github.io"
```

По умолчанию `*`. Указать конкретный домен безопаснее.

## Шаг 5. Настроить клиент

Откройте опубликованную страницу и в панели «Подключение» заполните:

* **Base URL** — адрес вашего прокси, например `https://evolute.example.com`
  (без завершающего слэша);
* **API_KEY** — ключ на чтение;
* **API_KEY_RW** — ключ на запись.

Нажмите «Сохранить», затем «Ping». Настройки сохраняются в
`localStorage` браузера и подтягиваются при следующем открытии.

---

## Безопасность

* Ключи `API_KEY` / `API_KEY_RW` вводятся в браузере и лежат в
  `localStorage` — **не открывайте клиент на чужом компьютере**.
* Никогда не коммитьте реальные `CAR_ID` / ключи / токены: страница на
  Pages публична, а вместе с ней публичен и весь репозиторий.
* Если нужен закрытый доступ — Pages в приватном репозитории требует
  платного тарифа; альтернатива — раздавать `evolute_client.html`
  тем же nginx, что стоит перед прокси (заодно исчезают проблемы с
  CORS и mixed content).

## Что ещё делает CI

`.github/workflows/ci.yml` на каждый push/PR проверяет, что
`evolute_api.py` компилируется и импортируется без ошибок. Это только
проверка синтаксиса, приложение при этом не запускается.
